# Auto-updater on Windows

Pecans provides a backend for the [Squirrel.Windows](https://github.com/Squirrel/Squirrel.Windows) auto-updater.

Refer to the [Squirrel.Windows documentation](https://github.com/Squirrel/Squirrel.Windows/tree/master/docs) on how to setup your application.

Pecans will serve NuGet packages on `http://download.myapp.com/update/win32/:version/RELEASES`.

Your application just need to configure `Update.exe` or `Squirrel.Windows` to use `http://download.myapp.com/update/win32/:version` as a feed url (:warning: without query parameters).

You'll just need to upload as release assets: `RELEASES`, `*-delta.nupkg` and `-full.nupkg` (files generated by `Squirrel.Windows` releaser).

## MSIX (Electron 41+)

Pecans can also serve updates to Windows apps packaged as MSIX. Electron 41's
`autoUpdater` consumes the same Squirrel.Mac-shaped JSON feed that
`/update/:platform/:version` already emits; the client just requests the msix
filetype:

```js
autoUpdater.setFeedURL(
  "http://download.myapp.com/update/win32-x64/" + version + "?filetype=msix"
);
```

Upload `.msix` (single-arch, e.g. `MyApp_1.0.0_x64.msix`) and/or
`.msixbundle` assets to your release. A `.msixbundle` is multi-arch by
definition and satisfies any Windows architecture; when both are published,
the bundle is preferred. Requesting `?filetype=msix` (or `msixbundle`) is
what routes to these assets — default Windows downloads keep resolving to the
`.exe` installer, and the Squirrel.Windows `RELEASES`/`.nupkg` flow is
unaffected.

On the discrete download route, msix is a package format:
`/dl/windows/64?pkg=msix` serves the x64 `.msix`, and
`/dl/windows/universal?pkg=msix` serves the `.msixbundle`.
